# 需求澄清流程

## 触发
计划Agent产出《商议摘要》后，Hermes统筹判定中等或复杂 → 启动此流程。

## 流程

### Phase 1: 分析师预探（如果预澄清阶段已探查则跳过）
创建分析师 → 探查项目环境 + 行业标准 → 产出《项目探查报告》≤200词。

### Phase 2: 红蓝辩论（需求辩论模式）
辩论裁判 + 红队 + 蓝队，3轮上限。2轮无新争议可提前收敛。

**每轮上下文压缩规则：**
- 第1轮：给全量《商议摘要》+《探查报告》
- 第2轮：只传争议摘要（≤5条）+ 上轮蓝队回应结论
- 第3轮：只传剩余争议（≤3条）

**红队职责**：扮演反对者/QA/极端用户，穷举边界条件、异常流程、安全风险。质疑蓝队方案的逻辑漏洞。
**蓝队职责**：正面回应每一条质询。无法回答则承认漏洞。构建并维护方案骨架。

### Phase 3: 收敛
辩论裁判产出《辩论结论纪要》— 四栏结构化（已验证事项/必须修复漏洞/建议优化项/已驳回质询）。

### Phase 4: 价值裁决
裁决Agent读取纪要 → 产出《裁决报告》— 两栏（必须修复 + 可延后优化）。

### Phase 5: 规范生成
规范生成Agent读取纪要+裁决报告 → 产出《需求规格说明书》和下游提示词（≤150词）。

### Phase 6: 用户确认门
Hermes统筹将《需求规格说明书》呈用户确认。用户说"go"或等效用词才进入开发阶段。
