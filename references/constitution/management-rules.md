# 管理宪法

> 动态文件。每次复盘产生新规则时追加。分层注入：只注入到适用角色。

## 元规则

| ID | 条款 | 适用角色 | 原子组 |
|----|------|----------|--------|
| M01 | 任何流程指令，凡不附带不可绕过之产出物及验证机制者，视为软建议，不视为规则。所有流程规则必须明确其必须产出的交付物和验证方式。无法被验证是否执行的规则，在设计和复盘时视为软建议，不具备强制力。 | 全体 | immutable |

## 注入规则
每条新条款附带 `适用角色` 元数据。分发时自动匹配——只给角色注入它适用的条款。

## 基础规则（v1.0 初始）

| ID | 条款 | 适用角色 | 原子组 |
|----|------|----------|--------|
| C01 | 代码提交前必须跑完整测试套件 | AI程序员, 开发执行, 前端开发 | - |
| C02 | 禁止在提交中包含密钥/密码/Token | 所有Codex侧Agent | - |
| C03 | Codex不可用时立即止损，不得空转等待 | 开发统筹 | - |
| C04 | 验收链优先级高于开发链 | 开发统筹 | - |
| C05 | 需求确认门不可跳过 | Hermes统筹, 计划Agent | - |
| C06 | 验收链(code-qa+func-qa)不可跳过，任何复杂度都必须走；单元测试全绿 ≠ 验收通过 | Hermes统筹 | - |
| C07 | 用户可见产项目(CLI/Web/App)，func-qa必须用浏览器/subprocess模拟真实用户操作验收 | func-qa | browser-acceptance |
| C08 | 用户可见产品必须浏览器实操验收：任何产出的最终形态是用户在浏览器或移动端可见的产品，func-qa必须执行浏览器实操验收三步走（打开浏览器、逐链接点击、深浅切换+移动端缩放）。不产出浏览器实操报告的项目，视为未完成验收，禁止交付。 | Hermes统筹, 开发统筹, func-qa | browser-acceptance |
| C09 | 验收链闸门不可跳过：模块二的验收链(code-qa+func-qa)是不可绕过的硬闸门。任何绕过验收链、自行判断代码通过的行为，视为流程违规。统筹的角色是调度验收、收集报告、根据报告放行——不是替代验收Agent自行裁决。 | Hermes统筹, 开发统筹 | browser-acceptance |
| H01 | Hermes统筹不得自行判断"测试全绿=验收通过"，必须委托专用的验收子Agent | Hermes统筹 | - |
