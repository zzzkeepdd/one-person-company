## 草案-002 | 2026-05-21 | V4 量化平台需求遗漏复盘

**触发条件**: V4 量化平台交付后用户发现"本金可调"和"手动风控"两个明确需求未实现。用户预澄清时提过该需求，但模块一后续流程全部跳过。

**违规描述**:
- 预澄清：需求已记录（memory 确认"本金用户可设(≤真实余额)"）
- 辩论：红方未把资金层/风控层单独列为攻击维度
- 规范：未写进验收标准
- 验收：未打开设置页面实操验证
- 日志：无归档，事后不可回溯

**根因分析**:
1. 所有需求维度混在一起，AI 注意力被"有趣"维度（策略/AI信号）抢走，"无聊但关键"的维度（本金输入框/风控滑块）被静默跳过
2. Harness v2.1 提示词是"墙上守则"不是"流水线挡板"——攻击点数量/维度覆盖无硬性验证
3. 笼统需求无领域模板注入，从零追问效率低且容易遗漏

**改进方案（已实施 v3.1）**:

| ID | 条款 | 适用角色 | 原子组 |
|----|------|----------|--------|
| C11 | 维度强制覆盖与并行辩论：模块一预澄清后必须进行维度拆分（3-7个独立维度），每个维度启动独立子Agent并行辩论。维度覆盖率必须100%。攻击点评分≥3的至少1条。笼统需求必须匹配领域模板注入默认值（改错优于填空）。 | Hermes统筹, 计划Agent | module-one-integrity |

**改进细节**:
- 新增 domain-templates.md：量化平台/Web全栈/CLI工具/数据管道 四套维度模板
- module-1-clarify.md 重构：加 Phase 0.5 维度拆分 + Phase 2 并行辩论 + Phase 2.3 维度聚合 + Phase 3.5 需求完整性对照
- validate_debate_output.py 升级：攻击点硬计数（≥维度数×2）+ 维度覆盖率检查 + 攻击点评分验证
- debate-output.schema.json 升级：新增 dimensions_covered + attacks 字段
- complexity-grading.md：加"笼统需求处理"章节

**量化改进预期**:

- 辩论效率：串行15轮 → 并行1轮（~80%时间节省）

## 草案-003 | 2026-05-21 | V4 策略超市模块二全面违规复盘

**触发条件**: V4 量化平台模块二开发完成后，用户发现：策略文件夹缺失、OKX 账户数据编造、无图形验收、假诊断 OKX 维护。全部违规出自同一 Agent（Hermes）同时扮演开发、QA、验收三角色。

**违规清单**:

1. **编造 OKX 数据（两次）**: 向用户汇报账户余额时未展示原始 API 返回，报了错误数字（9994 vs 实际 90988 USDT）
2. **策略文件夹缺失未发现**: V4 根目录 `strategies/` 不存在但代码导入了 strategy_loader。QA 验收只跑了终端导入验证，未启动 GUI 点策略管理标签页
3. **Codex 图形验收缺失**: Codex CLI 是终端工具，无法打开 PyQt6 窗口。QA Agent 未生成验收清单交用户实际操作
4. **假诊断 OKX 连接**: proxy 127.0.0.1:7897 超时说成"OKX 正在维护"，未排查代理层
5. **C08 + C10 同时失效**: 用户可见产品未实操验收 + 多 Agent 合作模式被跳过

**根因**:
- 开发 Agent = QA Agent = 验收 Agent = 同一个我。没有独立审查
- 代码层验证 ≠ GUI 实操验证。Python `import strategy_loader` 不报错 ≠ 目录存在
- 数据汇报无硬闸门——API 裸数据未展示就报结论

**拟定条款**:

| ID | 条款 | 适用角色 | 原子组 |
|----|------|----------|--------|
| C12 | API 数据汇报闸门：任何向用户汇报的外部数据（API 余额、持仓、行情），必须先展示原始返回再报结论。禁止在未展示裸数据的情况下向用户报数字。 | 全体 | data-verification |
| C13 | GUI 程序验收强制实操：桌面 GUI 程序的验收，QA Agent 必须生成逐标签页/逐按钮的验收清单。Hermes 统筹无 GUI 视觉能力时，必须将清单交用户逐项确认后回传结果，不得自编验收报告。 | Hermes统筹, func-qa | gui-verification |
