# 管理宪法 v2.0

> Codex+Hermes Harness v4.0 适用。动态文件。每次复盘产生新规则时追加。

## 元规则

| ID | 条款 | 适用角色 |
|----|------|----------|
| M01 | 任何流程指令，凡不附带不可绕过之产出物及验证机制者，视为软建议，不视为规则。 | 全体 |

## 基础规则

| ID | 条款 | 适用角色 |
|----|------|----------|
| C01 | 代码提交前必须跑完整测试套件 | Codex |
| C02 | 禁止在提交中包含密钥/密码/Token | Codex |
| C03 | Codex不可用时立即止损，不得空转等待 | Codex |
| C04 | 验收链优先级高于开发链 | Codex |
| C05 | 需求确认门不可跳过（L2保障模式除外） | Codex |
| C06 | 验收链(code-qa+func-qa)不可跳过 | Codex |
| C07 | func-qa必须用浏览器/subprocess模拟真实用户操作验收 | Codex |
| C08 | 用户可见产品必须浏览器实操验收：逐链接点击、深浅切换、375px移动端 | Codex |
| C09 | 验收链闸门不可跳过。统筹角色是调度验收——不是替代验收Agent。 | Codex |
| C10 | Codex 不得自行评估代码质量。必须经过 G4-1/G4-2 门禁。 | Codex |
| C11 | 维度拆分是硬性要求。即使只有一个维度也必须显式声明。 | Codex/Hermes |
| C12 | 攻击点硬计数：每个维度 ≥2 个攻击点，至少 1 个 ≥3 分。 | Hermes (G2) |
| C13 | 每个 testable attack 必须在执行清单中有对应验收测试。 | Codex (G3) |

## v2.0 新增（基于 Trae 对照实验）

| ID | 条款 | 适用角色 |
|----|------|----------|
| C27 | 测试即门：模块二 Step 1 产出代码文件无对应测试文件 → G4-1 自动 fail | Hermes (G4-1) |
| C28 | 最小验证集合：每个验证脚本含至少一个 golden negative case | Hermes |
| C29 | 无用户模式降级：用户跳过确认 → L2保障模式。跳过确认门，不跳过任何 gate。 | Codex |
| C30 | Gate 规则进化：复盘发现 gate 未拦住真实 bug → 更新对应 gate 检查规则。 | Hermes (G7) |
